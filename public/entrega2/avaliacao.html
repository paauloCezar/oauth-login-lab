GraphQL: Resource not accessible by integration (addComment)

Explicação: ao declarar permissions, toda permissão não listada fica como none. Sem pull-requests: write, o GITHUB_TOKEN só lê o código, e o gh pr comment é recusado. A IA rodou normalmente; só o passo de comentar falhou. Depois restaurei a permissão (https://github.com/paauloCezar/oauth-login-lab/actions/runs/38192396554).

  • Afirmação da IA irrelevante: no 2º comentário, a IA classificou como "Média" que github.base_ref "é interpolado diretamente no script de shell" e que "um nome de branch com metacaracteres pode alterar o comando". No nosso caso isso não é um risco real: base_ref é a ramificação de destino do PR (a main), que precisa já existir neste repositório, e só quem tem permissão de escrita aqui consegue criar ramificações. Quem abre um PR de fora controla o nome da ramificação de origem (head_ref), não o da de destino. Além disso, a IA não é consistente: o 3º comentário revisou o mesmo código e não repetiu esse alerta, e terminou oferecendo opções como "Fix all issues" e "criar SECURITY-REVIEW.md e fazer commit", que ela não tem como executar (é um comentário de PR, não uma conversa).

Problemas no esqueleto do PDF que precisei corrigir para a revisão funcionar:

  1. actions/ai-inference@v1 ainda é a versão antiga, que usa o GitHub Models e ignora o COPILOT_GITHUB_TOKEN (erro Cannot use 'in' operator to search for 'choices' in OK). Troquei para @v3, que usa o Copilot CLI.
  2. O modelo padrão da action (gpt-4.1) não estava disponível na conta (Model "gpt-4.1" from --model flag is not available). Coloquei model: "" para o Copilot escolher um modelo disponível.

Na revisão do PR #6, a IA fez três alertas que não se aplicam: disse que faltava permissão de acesso a modelos (isso era da v1, que usava o GitHub Models; a v3 usa o COPILOT_GITHUB_TOKEN), que o head -c falharia com pipefail (o GitHub só liga o pipefail quando o workflow declara shell: bash, e este não declara) e que github.event.before poderia vir só com zeros (só acontece no push que cria a main, que já existe).

Perguntas

  1. Por que o ci.yml roda duas vezes num push em ramificação com PR aberto, e qual execução o status check considera? O workflow escuta dois eventos: push (qualquer ramificação) e pull_request para a main, e um push numa ramificação com PR aberto dispara os dois. A execução de pull_request testa o resultado do merge da ramificação com a main, e é ela que representa o que vai entrar na main. As duas aparecem no PR com o nome verificar, ligadas ao último commit da ramificação, mas a de push testa esse commit sozinho e a de pull_request testa como ficaria depois do merge com a main. A regra só libera o merge se o verificar estiver aprovado.

  2. Por que um PR vindo de fork não consegue usar secrets.COPILOT_PAT, e qual ataque isso impede? No evento pull_request vindo de um fork, o GitHub roda o código escrito por quem fez o fork, e por isso não entrega os segredos do repositório de destino (o GITHUB_TOKEN também vem só com leitura). Isso impede que qualquer pessoa abra um PR que altera o workflow ou um script para imprimir ou enviar os segredos para fora, roubando o token.

  3. Por que a Tarefa 3 declara permissions em vez de usar o padrão do GITHUB_TOKEN? Pelo princípio do menor privilégio: o job só precisa ler o código (contents: read) e comentar no PR (pull-requests: write). Declarando isso, todo o resto fica sem permissão, então se o job for comprometido (uma action maliciosa, por exemplo), o token não consegue enviar código nem mexer em outras partes do repositório. O padrão do repositório pode ser mais amplo do que o necessário.

  4. A revisão da IA pode substituir o status check da Tarefa 2? Não. O status check é determinístico: o mesmo código sempre dá o mesmo resultado, e uma falha bloqueia o merge com uma regra clara (o SQL tem ou não tem erro). A IA não é assim: no PR #2 ela revisou o mesmo código duas vezes e deu respostas diferentes, apontou um risco que não existe (o base_ref) e ofereceu ações que não pode executar. A revisão da IA serve como uma segunda opinião para a pessoa ler e avaliar, mas não como critério automático de merge.

Arquivos do projeto

Conteúdo completo dos arquivos criados nesta avaliação, como estão na main.

.github/workflows/ci.yml

Tarefa 1: roda em todo push e em todo PR para a main. Procura segredos, aplica as migrações num SQLite local e valida o HTML.

name: ci
on:
  push:
  pull_request:
    branches: [main]
jobs:
  verificar:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v6
      - name: Procura segredos versionados
        run: |
          if git grep -nE "GOCSPX-|client_secret *= *['\"][^'\"]+" -- . ':!*.md' ':!.github/workflows/ci.yml'; then
            echo "::error::Possível segredo no repositório"; exit 1
          fi
      - name: Aplica as migrações D1 em um SQLite local
        run: |
          for f in migrations/*.sql; do sqlite3 -bail teste.db < "$f" || exit 1; done
          sqlite3 teste.db ".tables"
      - name: Valida HTML
        run: npx --yes htmlhint "**/*.html"

.github/workflows/revisao-ia.yml

Tarefa 3: a cada PR aberto ou atualizado, envia o diff para a IA e publica a resposta como comentário.

name: revisao-ia
on:
  pull_request:
    types: [opened, synchronize]
permissions:
  contents: read
  pull-requests: write
jobs:
  revisar:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v6
        with:
          fetch-depth: 0
      - uses: actions/setup-node@v6
        with:
          node-version: 22
      - run: npm install -g @github/copilot
      - name: Monta o prompt
        run: |
          {
            echo "Revise o diff de um site com Cloudflare Pages Functions e D1."
            echo "Aponte, em português e em até 10 itens: segredos expostos,"
            echo "SQL montado por concatenação em vez de prepare().bind(), e erros de lógica."
            echo '```diff'
            git diff origin/${{ github.base_ref }}...HEAD | head -c 20000
            echo '```'
          } > prompt.txt
      - id: ia
        uses: actions/ai-inference@v3
        env:
          COPILOT_GITHUB_TOKEN: ${{ secrets.COPILOT_PAT }}
        with:
          prompt-file: prompt.txt
          system-prompt: Você é um revisor de código objetivo.
          model: ""
      - name: Comenta no PR
        env:
          GH_TOKEN: ${{ github.token }}
        run: gh pr comment ${{ github.event.pull_request.number }} --body-file "${{ steps.ia.outputs.response-file }}"

.github/workflows/migrar.yml

Tarefa 4 e bônus: depois de um merge que altera migrations/, aplica as migrações no D1 remoto e escreve o resumo da IA na execução.

name: migrar
on:
  push:
    branches: [main]
    paths: ['migrations/**']
permissions:
  contents: read
jobs:
  aplicar:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v6
        with:
          fetch-depth: 0
      - uses: actions/setup-node@v6
        with:
          node-version: 22
      - run: npx --yes wrangler d1 migrations apply oauth-sessions-paulocezar --remote
        env:
          CLOUDFLARE_API_TOKEN: ${{ secrets.CLOUDFLARE_API_TOKEN }}
          CLOUDFLARE_ACCOUNT_ID: ${{ secrets.CLOUDFLARE_ACCOUNT_ID }}
      - run: npm install -g @github/copilot
      - name: Monta o prompt do resumo
        env:
          ANTES: ${{ github.event.before }}
        run: |
          {
            echo "Resuma em português, em até 5 itens curtos, o que as migrações D1 abaixo mudam no banco."
            echo "Para cada arquivo, diga o nome e o efeito (tabela, coluna ou índice criado ou alterado)."
            echo '```diff'
            git diff "$ANTES" HEAD -- migrations/ | head -c 20000
            echo '```'
          } > prompt-resumo.txt
      - id: resumo
        uses: actions/ai-inference@v3
        env:
          COPILOT_GITHUB_TOKEN: ${{ secrets.COPILOT_PAT }}
        with:
          prompt-file: prompt-resumo.txt
          system-prompt: Você resume migrações de banco de dados de forma objetiva.
          model: ""
      - name: Escreve o resumo na execução
        env:
          RESUMO: ${{ steps.resumo.outputs.response-file }}
        run: |
          {
            echo "## Migrações aplicadas (resumo da IA)"
            echo
            cat "$RESUMO"
          } >> "$GITHUB_STEP_SUMMARY"

Function usada na Tarefa 3, já corrigida com prepare().bind().

export async function onRequestGet({ request, env }) {
    const nome = new URL(request.url).searchParams.get("aluno") ?? "";
    const { results } = await env.DB.prepare(
        "SELECT * FROM notas WHERE aluno = ?"
    ).bind(nome).all();
    return Response.json(results, { headers: { "Cache-Control": "no-store" } });
}
